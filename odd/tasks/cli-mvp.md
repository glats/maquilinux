### Proposed implementation approach

1. Freeze the target and reproduce before fixing. Reuse the ISO path when suitable; discussion alone does not select a new disk-image pipeline.
2. Capture bounded boot/network tests, guest commands and failure/timeout evidence; greetings are insufficient.
3. Isolate contribution builds, signing and publication. Negative tests use fixture keys/repos. Authenticate bootstrap image/key; production credentials/services need separate authorization.
4. Verify/install/run/update one real package. Reject altered, unsigned and untrusted-key inputs before installation, preserving relevant installed state, not unrelated caches.
5. Explicit promotion and bounded recovery must prove package/metadata consistency; downgrade does not promise application-data or whole-OS rollback.
6. An external packager repeats the documented path; rehearse the full loop in a clean VM. Implement only verified gaps, not a replacement mql stack.
